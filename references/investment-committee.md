# G10 投决会对抗决策闭环（v3.10.0）

> 把 G3 的「单一反方审计」升级为「多 Agent 投决会对抗决策」——交付前最后一道**组织级协作决策层**。
> 与 G3（adversarial-auditor）、G8（benchmark）、G9（self-evolution）协同，是路线图点名的「组织级协作系统层」。

---

## 1. 背景与差距

- **G3 adversarial-auditor** 是"单一反方"：主分析完成后由一个挑战者挑刺，属于"事后审计"，不是"决策前多方对抗"。
- **真实投研决策是委员会制**：看涨 / 看跌 / 中性 / 风控多方角力，强制交叉质询，最终形成**有共识度与异议记录**的决议，且决议对报告主结论构成强约束。
- 本规范补齐该层：把"一个人挑刺"升级为"五委员对抗决策"，并让决议直接进入报告"综合建议"章节。

## 2. 五委员角色

| 角色 | 职责 |
|------|------|
| **主持委员（IC Chair）** | 主持流程、控时、强制交叉质询、汇总、按 §3 规则形成最终决议、记录异议、触发复核/HITL |
| **看涨委员（Bull）** | 论证买入 / 超配，列核心论据（≥3 条）+ 证据引用（provenance id） |
| **看跌委员（Bear）** | 论证卖出 / 低配 / 风险，逐条质疑看涨证据，给出下行情景 |
| **中性委员（Neutral）** | 指出现有证据不足以判断，列"证据缺口 / 须补充数据 / 情景假设"清单 |
| **风控委员（Risk）** | 检查适当性、合规红线、尾部风险、仓位 / 集中度 / 流动性限制；可一票**关注**但非一票否决（除非触碰合规红线则一票否决） |

> 角色可由现有子代理兼任（如 Bull=Bloomberg/行业分析师，Bear=adversarial-auditor 本体，Risk=合规/风控模块），由 orchestrator 在 Agent Teams 中编排。

## 3. 对抗决策协议（每个待决议题一轮）

1. **开题**：主持委员明确议题（标的 / 配置方向 / 时机 / 仓位）、决策框架与证据门槛。
2. **立场声明**：看涨 / 看跌各出"立场 + 核心论据（≥3 条）+ 证据引用（provenance id）"。
3. **证据缺口**：中性委员给"证据缺口 / 须补充数据"清单。
4. **强制交叉质询**：看跌须逐条回应看涨证据，看涨须回应看跌风险；主持委员记录关键交锋点（challenger / target / point / response）。
5. **风险结论**：风控委员给合规 / 风险结论（触红线则一票否决）。
6. **形成决议**：主持委员按规则产出 **投决会决议**：
   - `verdict ∈ {强力推荐 / 推荐 / 中性 / 谨慎 / 否决}`
   - `consensus`（0–1，按委员立场偏离度计：全员同向→1.0，两极分化→趋近 0）
   - `key_divergences`（top-3 主要分歧点）
   - `risk_plan`（若 verdict ∈ {推荐, 强力推荐} 须含止损 / 情景预案）
7. **异议记录**：任何委员可留 `dissent`（异议陈述 + 理由）。

## 4. 决议与报告主结论冲突处理

- 若投决会 `verdict ∈ {否决, 谨慎}` 而报告正文"综合建议"为"推荐 / 买入" → 触发 report-writer 复核，或升级 orchestrator 人工裁决（HITL）。
- 投决会决议须与报告"综合建议"章节**一致**，或显式说明差异及原因。
- 决议 `consensus` 与 G8 `benchmark_score`、G5 quality 三维度一并进入 G9 `evolution signals`（作为新的质量信号维度）。

## 6. 与 G3 / G8 / G9 协同

- **复用 G3**：adversarial-auditor 的 `challenges[]` 作为交叉质询素材，Bear 角色直接消费。
- **喂给 G9**：决议 `consensus` / `verdict` 作为新的质量信号维度写入 `evolution/signals/<delivery_id>.json`。
- **强约束报告**：决议是报告"综合建议"章节的硬约束（见 §4）。

## 7. 报告结构（第 19 章「投决会对抗决策与决议」）

- 委员席与角色
- 各委员立场与论据摘要（含证据引用）
- 交叉质询关键交锋
- 共识度评分（consensus 0–1）
- 最终决议（`verdict` + `consensus` + 主要分歧点 + 风险预案）
- 异议记录（dissent，若有）

## 8. 降级处置

- **投决会基础设施不可用**（角色代理失败 / 沙箱受限 / 编排超时）→ best-effort，不阻塞投递；在第 19 章（或声明处）标注「投决会基础设施不可用，本次未跑对抗决策」；不触发第十二道拦截但须明确声明。
- **纯研究 / 无投资建议的报告**（如仅做宏观复盘、无买卖结论）→ 可显式声明「本报告不纳入投决会对抗决策」。

## 9. 第十二道 fail-closed 校验逻辑（`check-investment-committee.sh`）

- 报告含「投决会对抗决策与决议」章节：
  - 须含 **决议条目**（`verdict` / `共识度` 标记）+（≥1 委员立场 或 「无委员立场记录」声明），否则拦截；
- 或含「本报告不纳入投决会对抗决策」豁免声明 → 放行；
- 均无 → 拦截。

> 校验为 fail-closed：缺失章节 / 空章节 / 无豁免声明，一律拦截投递，确保交付前必过组织级对抗决策层。

## 10. 验收样例（见 `技能优化方案/_pilot_g10_*.md`）

- `positive`：含第 19 章 + verdict + 共识度 + 委员立场 → 放行
- `negative`：含第 19 章但无 verdict/共识度 → 拦截
- `empty`：仅章节标题无内容 → 拦截
- `exempt`：含「本报告不纳入投决会对抗决策」→ 放行
