## 数据源标注规范（强制执行）

### 1. 标注格式

**每次获取数据后，必须在输出中标注（四要素强制 + 快照锚定强制，v3.1.0 起审计级核验）**：

```
数据来源：[来源名称](具体文章URL) — URL 为便利核验链接（可选追加 #:~:text= 锚点）
数据获取时间：YYYY-MM-DD HH:MM:SS
数据口径/定义：{指标口径说明，如"LPR 为贷款市场报价利率，分 1 年期/5 年期以上"}
关键假设：{分析所依赖的关键假设，如"以公报发布日版本为准，不含后续解读"}
快照索引：provenance/<source_id>.json  # 抓取时存档的不可变副本
被引片段：{被引用原文} @ [start_char, end_char]  # 锚定到快照副本字符区间
```

> ⚠️ 四要素缺一不可：来源、获取时间、口径/定义、关键假设。缺任一视为标注不完整。
> **权威核验依赖快照副本，不依赖活的 URL**：每条被引用的关键表述必须存档为 `provenance/<source_id>.json`，并标注其在快照中的字符区间 `[start_char, end_char]`。交付前 Hook 严格校验——被引片段必须真实存在于快照的字符区间内，缺失即拦截（fail-closed）。这是对接真实市场的"万无一失"底线。
> **URL 链接为便利项（强烈建议提供，便于人工跳转），但非核验依据**：宏观/政策类公开网页建议提供 URL；行情/API 类注明平台即可（如 AkShare 接口）。Text Fragment 锚点（`#:~:text=`）仅作 URL 的可选增强，依赖原页面未改+文字逐字一致+浏览器支持，可能失效，**不得**作为唯一核验手段。
> 原「数据更新频率」合并入「数据口径/定义」说明中（如"月频，每月15日左右更新上月数据"）。

### 1.1 快照存储规范（provenance）—— 审计级核验底座

每次研究在 workspace 下建立 `provenance/` 目录，每个被引用的数据源存为一个 `<source_id>.json` 不可变副本。**先存快照，再写报告**——引用时只写 `source_id` + 字符区间，不依赖活的网页。

**JSON 结构**：
```
{
  "source_id": "pbc_2026Q2_meeting",
  "source_name": "央行官网 pbc.gov.cn",
  "live_url": "http://www.pbc.gov.cn/xxx",
  "archived_url": "https://web.archive.org/web/20260326170000/xxx",
  "fetch_time": "2026-03-26T17:00:00+08:00",
  "caliber": "货币政策委员会例会通告原文",
  "assumptions": "以例会通告为准",
  "snapshot_text": "抓取时冻存的完整源文（不可变）",
  "quoted_spans": [
    {"text": "适时降准降息", "start": 1234, "end": 1240}
  ]
}
```

**抓取即存规则**：
- **网页类**（新华社/央行/统计局等）：调用 `https://web.archive.org/save?url=<live_url>` 获取永久存档链接写入 `archived_url`；同时把页面正文存入 `snapshot_text`。存档失败也至少保留本地快照文本。
- **A股公告类**：巨潮网下公告有稳定公告编号与 URL，`source_id` 用公告编号，`snapshot_text` 存公告正文。
- **行情/API 类**（AkShare）：`snapshot_text` 存接口返回原始数据 + 时间戳，`source_id` 用 `akshare_<标的>_<指标>_<日期>`。

**核验逻辑**：报告里每条被引片段 → 在 `provenance/<source_id>.json` 的 `snapshot_text` 中定位 `quoted_spans` 的 `[start, end]`，确认片段真实存在。Hook `verify-provenance.py` 在交付前自动执行，缺快照/缺区间/片段不符即拦截（fail-closed）。

**示例1（股票行情）**：
```
数据来源：[AkShare/东方财富](https://quote.eastmoney.com)（实时行情接口）
数据获取时间：2026-05-18 16:30:00
数据口径/定义：实时行情（前收盘价/今开/最高/最低/最新价），延时约15秒，非逐笔成交
关键假设：以收盘时点快照为准，盘中高频波动未纳入
```

**示例2（宏观数据）**：
```
数据来源：[AkShare/国家统计局](https://www.stats.gov.cn)（CPI 月度数据）
数据获取时间：2026-05-18 16:30:00
数据口径/定义：CPI 同比（对比上年同月），月频，每月15日左右更新上月数据
关键假设：以国家统计局初次公布值为准，未纳入后续修订值
```

### 3. 禁止行为（红线）

| 禁止行为 | 说明 | 后果 |
|----------|------|------|
| ❌ 伪造数据 | 编造不存在的数据 | 严重错误，必须杜绝 |
| ❌ 不标注来源 | 使用数据但不标注来源 | 违反规范，必须修正 |
| ❌ 混淆数据源 | 将AkShare数据标注为Wind | 误导用户，必须修正 |
| ❌ 使用过期数据 | 未标注数据获取时间，用户误以为是最新数据 | 可能误导决策 |

## 投资者适当性匹配（P1缺陷修复）

### 1. 风险承受能力等级（投资者）

| 等级 | 名称 | 特征 | 适合产品风险等级 |
|------|------|------|-----------------|
| C1 | 保守型 | 不能承受任何损失，只接受保本产品 | R1（低风险） |
| C2 | 稳健型 | 能承受小幅波动，追求稳定收益 | R1-R2（中低风险） |
| C3 | 平衡型 | 能承受中等波动，追求资产增值 | R1-R3（中风险） |
| C4 | 进取型 | 能承受较大波动，追求高收益 | R1-R4（中高风险） |
| C5 | 激进型 | 能承受大幅波动，追求最高收益 | R1-R5（所有风险） |

### 2. 产品风险等级（基金/股票/投资组合）

| 等级 | 名称 | 典型产品 | 最大回撤参考 |
|------|------|----------|--------------|
| R1 | 低风险 | 货币市场基金、国债 | <2% |
| R2 | 中低风险 | 纯债基金、稳健理财 | 2%-5% |
| R3 | 中风险 | 混合基金、指数基金 | 5%-20% |
| R4 | 中高风险 | 股票基金、行业主题基金 | 20%-40% |
| R5 | 高风险 | 杠杆产品、衍生品、单只股票 | >40% |

### 3. 适当性匹配规则

```
投资者等级 ≥ 产品风险等级 → 适合购买
投资者等级 < 产品风险等级 → 不适合购买，需在报告中明确警示
```

**示例**：
- C3投资者 + R2产品 → ✅ 适合
- C3投资者 + R4产品 → ❌ 不适合，需警示

### 4. 风险测评问题模板（首次分析前使用）

**当用户未提供风险承受能力时，AI必须先进行适当性评估**：

```
为了给您提供合适的投资建议，请先完成风险测评（以下问题请如实回答）：

1. 您的投资经验如何？
   A. 无经验（新手）
   B. 少于1年
   C. 1-5年
   D. 5年以上

2. 您能承受的最大亏损是多少？
   A. 不能接受任何亏损
   B. 最大亏损5%
   C. 最大亏损10%-20%
   D. 最大亏损20%以上

3. 您的投资目标是什么？
   A. 保本为主，收益次要
   B. 稳定收益，小幅波动可接受
   C. 资产增值，可接受中等波动
   D. 追求高收益，可接受大幅波动

（根据用户回答，AI自动评估投资者等级C1-C5，并在报告中标注）
```

### 5. 报告中的适当性提示模板

**当分析结果涉及具体投资建议时，必须在报告中添加**：

```
---

【投资者适当性提示】

根据您的风险测评结果，您的风险承受能力等级为：C{x}（{等级名称}）

本次分析涉及的基金/股票风险等级为：R{y}（{风险名称}）

{适合/不适合}您的风险承受能力。
{如不适合，添加：⚠️ 强烈建议您重新评估风险承受能力，或选择风险等级更低的产品。}

---
```

### 6. 禁止行为（红线）

| 禁止行为 | 说明 | 后果 |
|----------|------|------|
| ❌ 跳过适当性评估 | 未评估投资者风险承受能力就给出投资建议 | 违反合规要求 |
| ❌ 隐瞒风险等级 | 不告知用户产品风险等级 | 误导用户，可能承担赔偿责任 |
| ❌ 强行推荐 | 向不适合的投资者推荐高风险产品 | 严重违反合规要求 |
